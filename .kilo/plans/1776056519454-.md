# Plan: Mobile Portrait Layout for Mushroom Craft

## Problem
The game currently uses a fixed 800x600 landscape canvas with `Phaser.Scale.FIT` + `CENTER_BOTH`. On mobile portrait displays, this renders as a small landscape box centered in the middle of the screen with large black bars above and below.

## Approach: RESIZE Scale Mode with Responsive Layout

After researching Phaser 3's Scale Manager, the best approach for a truly responsive portrait game is:

- **Scale mode: `Phaser.Scale.RESIZE`** — The canvas dynamically resizes to fill the entire parent element, regardless of aspect ratio. This eliminates letterboxing entirely.
- **All scene layouts use `this.scale.width` / `this.scale.height`** instead of hardcoded pixel values, so UI elements reposition correctly at any screen size.
- **Portrait-first design** — Game dimensions change to a portrait aspect ratio (e.g., 400x700 as the "design" baseline), but actual runtime dimensions adapt to the device.

Why not FIT? FIT maintains a fixed aspect ratio and always produces letterboxing. RESIZE fills the screen completely and lets us reposition elements responsively — exactly what a UI-heavy game needs.

## Changes

### 1. `index.html` — CSS for full-screen canvas
- Add `height: 100%` to `html` and `body` to ensure the canvas parent fills the viewport
- Add `touch-action: none` to prevent browser gesture interference on mobile
- Update viewport meta to prevent zoom: `user-scalable=no, maximum-scale=1`

### 2. `src/main.ts` — Game config for RESIZE mode
- Change `width`/`height` to portrait design size: `400` x `700`
- Change `scale.mode` from `Phaser.Scale.FIT` to `Phaser.Scale.RESIZE`
- Keep `autoCenter: Phaser.Scale.CENTER_BOTH`
- Add `scale.parent: document.body`

### 3. `src/scenes/MainScene.ts` — Responsive mushroom house drawing
- Replace all hardcoded pixel positions (800, 600, 400, etc.) with calculations based on `this.scale.width` and `this.scale.height`
- The mushroom house background will scale and reposition to fit any canvas size
- Key positions (center x, ground y, etc.) become derived values:
  - `cx = this.scale.width / 2`
  - `groundY = this.scale.height * 0.6`
  - All other positions calculated as fractions of width/height

### 4. `src/scenes/HUDScene.ts` — Responsive HUD bar
- Money text positioned relative to top-left with padding
- Tab buttons laid out relative to `this.scale.width` — evenly distributed across the top
- Each button width calculated from available space
- Listen to `this.scale.on('resize', ...)` to reposition elements when the screen changes

### 5. `src/scenes/UIScene.ts` — Responsive UI panels
This is the largest change. Every hardcoded position needs to be relative:
- **Panel background**: `this.scale.width` × `this.scale.height` instead of 760×480
- **Close button**: positioned relative to panel top-right corner
- **Crafting UI**: ingredient grid columns/rows computed from available width
- **Selected ingredient pane**: slots stacked vertically instead of side-by-side on narrow screens
- **Craft button**: centered horizontally
- **Inventory grid**: columns/cell sizes computed from width
- **Shop grid**: columns/cell sizes computed from width
- **Customer cards**: full-width cards with sell button positioned relative to card width

**Helper method**: Add a `getLayout()` method that returns commonly used dimensions:
```ts
private getLayout() {
  const w = this.scale.width;
  const h = this.scale.height;
  return {
    w, h,
    centerX: w / 2,
    panelPadding: 20,
    panelW: w - 40,
    panelH: h - 80,
    panelX: 20,
    panelY: 60,
    cellW: Math.min(140, (w - 80) / 5),
    cellH: 50,
    fontSize: w < 500 ? '10px' : '14px',
    titleFontSize: w < 500 ? '16px' : '20px',
  };
}
```

### 6. Add `resize` event handling to all scenes
Each scene with positioned elements needs to listen for resize events and update positions:
```ts
this.scale.on('resize', this.handleResize, this);
```
For HUDScene and UIScene, this means repositioning existing game objects rather than destroying/recreating them (for performance). For MainScene, the simplest approach is to clear and redraw the graphics.
